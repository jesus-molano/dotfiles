# To Spec

Write a decision-ready spec, not a narrative.

Include: problem and user outcome; in-scope and out-of-scope behavior; users and scenarios; functional and non-functional requirements; data/contracts; error and edge behavior; acceptance criteria; rollout or migration; observability; dependencies; open decisions.

Use observable language: each acceptance criterion states setup, action, and expected result. Trace every requirement to a scenario and flag requirements without a verification method. Link evidence rather than copying confidential material. Ask focused questions for decisions that change behavior, cost, or risk; make provisional assumptions conspicuous.
